## 💡 入门：什么是张量？

在本课程的数值计算语境中，张量（tensor）可以理解为“多维数组”，是机器学习中保存数据的基本容器。它能表示一个数、一排数、一张表，或者多张表组成的数据。

```
张量的维数：
0 维：标量（scalar）  5.0                  一个数
1 维：向量（vector）  [1, 2, 3]            一排数
2 维：矩阵（matrix）  [[1, 2], [3, 4]]     按行列排列的数
3 维：多层数组       [[[...]], [[...]]]    一叠矩阵
```

**先分清“维数”“形状”和“元素个数”**：

- `shape` 是形状，记录每条轴有多长。例如两行三列的数组形状是 `(2, 3)`。
- `ndim` 是维数，也就是轴（axis）的数量；`(2, 3)` 有两条轴，所以是二维。
- `size` 或 `numel()` 是元素总数；两行三列共有 `2 × 3 = 6` 个元素。
- 标量形状为 `()`，没有轴，但有一个元素。一维数组 `[5.0]` 的形状是 `(1,)`，与标量不同。括号中的逗号表示这是只有一项的 Python 元组。

“一个有 3 个分量的向量”存入数组后通常是**一维数组**，形状为 `(3,)`；不要把向量长度 3 与数组的维数混淆。

计算时，张量会经过一系列操作，就像原料依次通过加工步骤：

```
数据处理流程：
输入数据 → 第一次变换 → 第二次变换 → …… → 最终结果
(行数, 列数)  (行数, 新列数)  (行数, 更新列数)  (行数, 输出列数)
```

例如每行代表一位同学，每列代表一科成绩，一张成绩表就是二维张量。计算每位同学的总分，会把形状从 `(学生数, 科目数)` 变成 `(学生数,)`。

从简单统计到大规模科学计算，多维数组都是通用的数据容器。理解张量，就是理解数值计算的重要基础。

### 张量为什么对机器学习系统重要？

成熟框架中的张量，除了数值，还可能关联内存布局、所在设备以及用于自动求导的运算记录。

```
典型机器学习流程：
原始文件 → 数据预处理 → 创建张量 → 执行计算 → 输出张量
             NumPy 数组           CPU 或 GPU

本章实际实现：
Python 数据 / NumPy 数组 → Tensor 包装 → NumPy 在 CPU 上计算
```

**CPU** 是通用处理器；**GPU** 擅长并行处理大量相似运算。**计算图**记录“结果由哪些操作得到”，训练时可以据此反向计算梯度。这些是理解完整框架的背景知识；本章的 `Tensor` 基于 NumPy，在 CPU 上运行，当前没有实现 GPU 后端或自动求导计算图。

**核心认识**：张量把数学中的数字、向量和矩阵，与程序中的存储方式和运算接口连接起来。

## 📐 基础：需要掌握的数学概念

### 本章会实现哪些核心操作？

下面这些操作为后续神经网络组件提供基础：

| 操作类别 | 接口 | 最初可以怎样理解 |
|---|---|---|
| 逐元素运算 | `+`、`-`、`*`、`/` | 对应位置分别进行加、减、乘、除 |
| 矩阵运算 | `@`、`matmul()` | 按“行与列做点积”的规则组合数据 |
| 形状与轴操作 | `reshape()`、`transpose()` | 调整数据分组方式，或交换轴 |
| 归约运算 | `sum()`、`mean()`、`max()` | 把一组数汇总为和、均值或最大值 |

“归约”（reduction）就是把多个值汇总成较少的值，例如把 `[1, 2, 3]` 求和得到 `6`。归约可能改变形状，但与仅调整形状的 `reshape()` 含义不同。

### 广播：让不同形状的数据参与运算

广播（broadcasting）是 NumPy 按形状规则对齐数据的一种机制。满足规则时，不必手动把较小的数组重复成大数组。

```
标量 + 向量：
5 + [1, 2, 3]
可理解为 [5, 5, 5] + [1, 2, 3]
结果为 [6, 7, 8]

矩阵 + 一维向量：每一行加上同一个向量
[[1, 2], [3, 4]] + [10, 20]
= [[1, 2], [3, 4]] + [[10, 20], [10, 20]]
= [[11, 22], [13, 24]]
形状：(2, 2) + (2,) → (2, 2)

矩阵 + 二维列向量：每一行加上一个指定的数
[[1, 2],   [[10],     [[10, 10],     [[11, 12],
 [3, 4]] +  [20]]  →  [20, 20]]  →  [23, 24]]
形状：(2, 2) + (2, 1) → (2, 2)
```

留意：`[10, 20]` 的形状是 `(2,)`；`[[10], [20]]` 的形状是 `(2, 1)`，广播方向不同。后文会介绍从最右侧开始逐轴对齐的规则。

### 内存布局：二维表格在内存里怎样存放？

内存可以先想象成一排连续的小格子。NumPy 新建数组通常采用行优先的 C 顺序，即先存完第一行，再存第二行；NumPy 也支持列优先数组和不连续的数组视图，因此不能认为所有数组都按同一种方式存储。

```
以按行连续存储的 2×3 矩阵为例：
矩阵：             内存中的元素顺序：
[[1, 2, 3],        [1][2][3][4][5][6]
 [4, 5, 6]]         第一行    第二行

按行访问：1 → 2 → 3，访问位置相邻
按列访问：1 → 4，跨过中间的一些元素
```

**缓存（cache）**是 CPU 附近容量较小、读取较快的存储。处理器通常一次把邻近的一批数据载入缓存，因此顺序访问大数组往往更有利于复用已经读入的数据，这称为“缓存局部性”。

上面的小矩阵只是说明访问顺序；它很可能整体都在缓存中，不能据此断言“读第二个列元素必然缓存未命中”。真实速度还取决于数组大小、步长和硬件等因素。

## 🏗️ 实现：搭建张量基础

接下来按功能逐步理解 `Tensor` 类，并用相应测试检查每一部分。

### Tensor 类的结构

```
Tensor
├─ 核心属性
│  ├─ data：NumPy 数组，保存实际数值
│  ├─ shape：元组，记录各轴的长度
│  ├─ size：整数，记录元素总数
│  └─ dtype：数据类型，本章统一为 float32
├─ 算术与矩阵运算
│  ├─ __add__、__sub__、__mul__：加、减、逐元素乘
│  ├─ __truediv__：逐元素除法
│  └─ matmul()：矩阵乘法
├─ 形状、归约与索引
│  ├─ reshape()、transpose()：调整形状或交换轴
│  ├─ sum()、mean()、max()：求和、均值和最大值
│  └─ __getitem__：索引与切片
└─ 辅助接口
   ├─ __repr__()、__str__()：生成便于查看的文字表示
   ├─ numpy()：取得底层 NumPy 数组
   ├─ memory_footprint()：统计数值数组占用的字节数
   └─ ndim、numel()、contiguous()：维数、元素数、连续存储副本
```

以双下划线开头和结尾的方法叫“特殊方法”或“魔术方法”。例如 `a + b` 会调用相应的 `__add__`，`a[0]` 会调用 `__getitem__`。这样自定义类也能使用熟悉的 Python 运算符。

`ndim` 是属性，写作 `x.ndim`；`numel()` 是方法，写作 `x.numel()`。先理解接口分别回答什么问题，再记名字会更容易。

整个设计围绕两个任务展开：保存数值，以及通过统一接口操作数值。

### 张量的创建与初始化

实现运算前，先理解张量如何保存数据并记录属性。构造器 `__init__` 会在执行 `Tensor(...)` 时被调用，负责把新对象准备好。

```
初始化流程：
输入数据 → 必要的预处理 → NumPy 数组 → 记录张量属性 → 可以参加运算
[1, 2, 3]                 float32      shape=(3,)       + - * / @
                               ↓
                          分配数组存储空间

二维输入示例：
[[1, 2, 3], [4, 5, 6]]
         ↓
创建保存这些数值的 NumPy 数组
         ↓
记录 shape=(2, 3)、size=6、dtype=float32
```

**包装（wrapper）是什么意思？**  
`Tensor` 内部用 `self.data` 保存 NumPy 数组，再为它增加统一的运算方法。例如 `Tensor([1, 2, 3])` 创建了一个外层对象，底层数值实际保存在 `tensor.data` 中。

**数据类型 `float32` 是什么？**  
它是使用 32 位存储一个数的浮点类型，通常占 4 字节，能表示小数。构造器使用 `np.array(data, dtype=np.float32)` 统一类型，因此输入整数 `1` 也会作为浮点数保存。浮点数精度有限，后面的测试会用 `np.allclose` 比较允许微小误差的结果。

如果输入是由 `Tensor` 组成的非空列表，构造器会先提取各自的数据，用 `np.stack` 沿新轴组合，然后再创建数组；普通的类型转换与不合法输入检查主要交给 NumPy。

**本实现的内存行为**：`np.array(..., dtype=np.float32)` 会创建数组副本。即使传入已有的 NumPy 数组，也不能把这里的构造过程当作零拷贝。这还会影响后续将结果重新包装为 `Tensor` 的运算。

**为什么采用这种方式？**

- **性能基础**：NumPy 的许多数值运算由编译后的底层代码执行。
- **兼容性**：便于与 Python 科学计算生态中的数组接口衔接。
- **便于教学**：把重点放在张量接口、形状规则和运算逻辑上，而不用从内存分配器开始实现。
- **逐步扩展**：统一接口有助于以后理解其他计算后端；当前代码仍然只使用 NumPy 在 CPU 上计算，GPU 支持需要额外实现。

这里可以用 `(x - 2) / 2` 组合多个运算；“运算可以串起来”并不表示已经记录了自动求导计算图。

## 🏗️ 逐元素四则运算

逐元素（element-wise）运算对数组中对应位置的数分别计算；形状不同时，可能先按照广播规则对齐。

### 这些操作为什么重要？

数值处理中的许多步骤都由简单的逐元素运算组成：

- **缩放**：每个元素乘同一个数，例如把米换算成厘米。
- **阈值处理**：按条件保留或截断数值，例如把负数设为零；这通常还需要比较或激活函数操作。
- **中心化**：每个元素减去均值，让数据围绕零分布；中心化常是标准化的第一步。
- **比较差异**：逐位置相减，查看两组数据各项相差多少。

### 从逐元素加法开始

```
向量相加：
[1, 2, 3] + [4, 5, 6]
= [1+4, 2+5, 3+6]
= [5, 7, 9]

矩阵相加：
[[1, 2],   [[5, 6],   [[1+5, 2+6],   [[6, 8],
 [3, 4]] +  [7, 8]] =  [3+7, 4+8]] =  [10, 12]]

矩阵与列向量广播相加：
[[1, 2],   [[10],     [[1, 2],   [[10, 10],   [[11, 12],
 [3, 4]] +  [20]]  =  [3, 4]] +  [20, 20]] =  [23, 24]]
 (2, 2)    (2, 1)                 按列扩展       (2, 2)
```

这里的“列向量”是形状为 `(2, 1)` 的二维数组，每行只有一个数；它与形状为 `(2,)` 的一维数组有不同的广播行为。

**广播规则**：

1. 从最右侧的轴开始对齐形状。
2. 每一对轴的长度必须相等，或者其中一个长度为 `1`。
3. 一方缺少的左侧轴，视为长度为 `1`。

例如 `(3, 2) + (2,)` 可以先看成 `(3, 2) + (1, 2)`，结果是 `(3, 2)`。`(3, 2) + (3,)` 则不能广播，因为最右侧的 `2` 与 `3` 既不相等，也都不是 `1`。

**批处理中的用途**：一个批次（batch）包含多条样本。若数据形状是 `(样本数, 特征数)`，可以给整个批次加上形状为 `(特征数,)` 的偏置向量，含义是“每条样本的同一特征都加上同一个偏移量”。

**内存方面**：广播规则本身通常不需要先创建一整份重复输入；NumPy 可以按需读取相应位置。但运算结果仍要占内存，本章将结果包装成 `Tensor` 时还会复制数据，所以广播并不等于整个计算完全没有分配。

### 减法、乘法与除法

这些操作与加法类似，都对对应位置分别计算，并支持广播。

| 操作 | 计算示例 | 常见用途 |
|---|---|---|
| 减法 | `[6, 8] - [1, 2] = [5, 6]` | 用 `x - mean` 对数据做中心化 |
| 逐元素乘法 | `[2, 3] * [4, 5] = [8, 15]` | 用 `x * mask` 保留、屏蔽或缩放指定位置 |
| 除法 | `[8, 9] / [2, 3] = [4.0, 3.0]` | 用 `x / std` 按给定尺度缩放特征 |

`mean` 表示均值；`std` 通常表示标准差，用来衡量数据的离散程度；`mask` 是掩码，例如乘 `[1, 0, 1]` 会保留第一个和第三个值，把第二个值变成零。这里说的乘法是 `*`，矩阵乘法使用 `@`。

```
与标量广播运算：
[1, 2, 3] * 2 = [2, 4, 6]      每个数都扩大为原来的两倍
2 * [1, 2, 3] = [2, 4, 6]      标量在左侧也支持相同运算
[1, 2, 3] - 1 = [0, 1, 2]      每个数都减去 1
[2, 4, 6] / 2 = [1, 2, 3]      每个数都缩小为原来的一半

标准化的形状示意：
batch_data = [[1, 2], [3, 4], [5, 6]]  # 形状为 (3, 2)：3 条样本、2 个特征
mean = [3, 4]                           # 形状为 (2,)：每个特征对应一个均值
std = [2, 2]                            # 形状为 (2,)：本例给定的缩放尺度

# 标准化公式：先减均值，再除以每个特征的标准差
normalized = (batch_data - mean) / std
# 广播形状：(3, 2) - (2,) → (3, 2)，再除以 (2,) → (3, 2)
# 本例结果：[[-1, -1], [0, 0], [1, 1]]
```

上述代码块用于说明数值和形状，普通 Python 列表不能直接做这些减法和除法。实际运行时，需要把 `batch_data`、`mean`、`std` 都包装为 `Tensor` 或转换成 NumPy 数组。`std=[2, 2]` 在这里是给定的尺度；按总体标准差或样本标准差计算，会得到不同结果，不能不加说明地混用。

**标准化与归一化**：术语在不同资料中可能略有差别。本例的“标准化”特指 `(x - 均值) / 标准差`；而“归一化”也可能指缩放到 `[0, 1]` 或单位长度。简单地除以 `2` 只能称为缩放，不一定已经达到某种标准化目标。实际标准化还要处理标准差为零的情况。

**运算顺序**：`2 * x` 与 `x * 2` 数值相同，但 `10 - x` 与 `x - 10`、`12 / x` 与 `x / 12` 不同；本类提供相应的反向运算方法以保留正确顺序。

**性能说明**：NumPy 的逐元素运算常由优化的底层代码完成，并可能使用 SIMD，即“一条指令同时处理多个数”的处理方式。实际速度取决于硬件、数据规模和内存访问。

**⚠️ 广播容易造成的隐蔽错误**：

```
预测值 predictions 的形状：(32, 4)  ← 32 条样本，每条 4 个输出
目标值 targets 的形状：    (4,)     ← 如果遗漏了每条样本各自的目标，就有问题

NumPy 可以把 (4,) 广播到 (32, 4)：
32 条样本都会使用同一组目标值，运算依然能够执行。
```

如果本意就是所有样本共用同一个向量，这种广播完全合理；如果每条样本应有不同目标，这就是计算能够运行、含义却错误的情况。计算预测误差或损失前，应核对每条轴的含义以及预期形状，而不只检查程序是否报错。

### 🧪 单元测试：四则运算

本测试检查张量与张量、张量与标量之间的加减乘除，以及不同形状下的广播行为。标量写在张量左边或右边时，都应符合数学含义。

**检查内容**：加法、减法、逐元素乘法、除法、标量反向运算及广播。  
**为什么要检查**：批处理、数据中心化和特征缩放都依赖这些基础能力。  
**预期结果**：数值正确，广播方向符合预期，连续组合运算仍能得到正确结果。

测试还故意构造一个目标形状不匹配的例子，提醒我们关注数据含义；“可以广播”只说明形状规则允许计算，不保证它符合任务需求。

## 🏗️ 矩阵乘法：核心计算操作

矩阵乘法与逐元素乘法的规则不同：逐元素乘法只把对应位置的数相乘；矩阵乘法把左矩阵的一行与右矩阵的一列“对应相乘再求和”，得到一个输出值。

这样的“对应相乘再求和”叫**点积（dot product）**。它会把多个输入特征组合起来，是线性变换的基础。例如新成绩可以是 `语文 × 0.4 + 数学 × 0.6`，其中 `0.4`、`0.6` 就是组合输入的权重。

### 矩阵乘法为什么重要？

科学计算和数据处理经常用一个矩阵统一描述一组线性变换：

```
线性变换：
输入数据          @ 变换矩阵          = 输出数据
(N, D_in)         @ (D_in, D_out)     → (N, D_out)

N：样本数；D_in：每条样本的输入特征数；D_out：输出特征数。

降维示例：
32 条样本         @ 投影矩阵          = 投影后的样本
(32, 784)         @ (784, 256)        → (32, 256)

每条样本从 784 个特征变成 256 个特征，样本数仍为 32。
```

“投影矩阵”在这里指把数据映射到另一组特征表示的矩阵。输出维数减少不自动意味着保留了最重要的信息，效果还取决于矩阵的取值或学习方式。

### 一步步观察矩阵乘法

```
A 的形状为 (2, 3)       B 的形状为 (3, 2)
A = [[1, 2, 3],        B = [[7, 8],
     [4, 5, 6]]             [9, 1],
                             [1, 2]]

C = A @ B
  = [[1×7+2×9+3×1, 1×8+2×1+3×2],
     [4×7+5×9+6×1, 4×8+5×1+6×2]]
  = [[28, 16],
     [79, 49]]

按输出位置拆开：
C[0,0] = A[0,:] · B[:,0] = [1,2,3] · [7,9,1] = 28
C[0,1] = A[0,:] · B[:,1] = [1,2,3] · [8,1,2] = 16
C[1,0] = A[1,:] · B[:,0] = [4,5,6] · [7,9,1] = 79
C[1,1] = A[1,:] · B[:,1] = [4,5,6] · [8,1,2] = 49

二维矩阵乘法的形状规则：
A(m, n) @ B(n, p) → C(m, p)
     ↑        ↑
这两个内侧维度必须相等
```

Python 索引从 `0` 开始。`A[0, :]` 表示第一行的所有列，`B[:, 0]` 表示第一列的所有行，冒号 `:` 在这里表示“该轴上的全部位置”。

### 计算量与性能

**计算复杂度**描述问题变大时需要多少计算，不直接等于耗时。对于 `(M, K) @ (K, N)`，输出有 `M × N` 个位置，每个位置需要长度为 `K` 的点积：

```
乘法次数：M × N × K
加法次数：M × N × (K - 1)
浮点运算次数约为：2 × M × N × K
复杂度记作：O(MNK)

例如两个 1000×1000 矩阵相乘：
约需 2 × 1000³ = 20 亿次浮点运算。
```

**FLOPs**表示浮点运算次数；**FLOP/s**表示每秒能完成多少次浮点运算。如果有效速度是每秒 10 亿次，完成约 20 亿次需要约 2 秒；若有效速度是每秒 200 亿次，则约需 0.1 秒。这只是“计算量 ÷ 实测速率”的示意，CPU 的 1 GHz 时钟频率不等于每秒 10 亿次浮点运算，不能据此给出固定运行时间。

在常见的按行连续数组中，朴素算法对 A 按行读取、对 B 按列读取、对 C 按行写入。大矩阵的按列访问可能不利于缓存复用。OpenBLAS、Intel MKL 等优化的线性代数库通常采用：

- **分块**：把矩阵切成能较好利用缓存的小块来计算。
- **向量化**：借助 SIMD 同时处理多个数。
- **并行化**：把工作分配给多个 CPU 核心。

**对应到本章代码**：两个二维矩阵相乘时，`matmul` 使用两层 Python 循环遍历输出位置，每个位置调用一次 `np.dot`；其他维数组合交给 `np.matmul`。前者便于观察点积规则，但不能当作一次调用优化库完成整个二维矩阵乘法的实现，Python 循环也会带来额外开销。

### 连续进行矩阵乘法

```
输入：(100, 50)，即 100 条样本、每条 50 个特征
  ↓ 乘 A，A 的形状为 (50, 20)
中间结果：(100, 20)
  ↓ 乘 B，B 的形状为 (20, 5)
最终结果：(100, 5)

特征数变化：50 → 20 → 5
样本数一直保持为 100。

两次乘法的浮点运算次数约为：
100 × (2×50×20 + 2×20×5)
= 100 × (2000 + 200)
= 220000，即约 22 万次。
```

如果两次线性变换之间没有激活函数等非线性操作，它们在数学上还可以合成为一次线性变换。`(X @ A) @ B` 与 `X @ (A @ B)` 数学上等价，实际浮点计算可能有微小舍入差异，计算成本也会因中间矩阵大小而不同。

这类运算量会随数据规模快速增长，因此缓存优化、并行计算及硬件加速对大型模型十分重要。

### 矩阵乘法的输入与形状检查

开始计算前，要先检查两个操作数是否适合相乘。本模块把常见问题分成三类，并给出便于定位原因的异常信息。

1. **类型检查**：右侧必须是 `Tensor`。如果是 Python 数字、列表或原始 NumPy 数组，应按需先包装为 `Tensor`。
2. **标量检查**：任何一方都不能是零维标量，因为标量没有可用于矩阵乘法的轴。将整个张量乘以某个数，应使用 `*`。
3. **内维度检查**：对于二维情况，`A(M, K) @ B(K, N)` 中的两个 `K` 必须相等。

```
_validate_matmul_shapes 检查流程：
├─ 右侧不是 Tensor？     → TypeError：操作数类型不正确
├─ 任一操作数为 0 维？   → ValueError：应使用标量乘法 *
├─ 适用的内维度不匹配？  → ValueError：形状不兼容
└─ 通过检查               → 进入乘法计算
```

`TypeError` 表示传入的数据类型不符合要求；`ValueError` 表示类型可以接受，但值或形状不适合当前操作。

一维向量没有“行数、列数”两个轴，需要使用向量特例：例如 `(M, K) @ (K,)` 得到 `(M,)`，两个长度为 `K` 的向量相乘得到标量。三维及以上数组还可能带有批次轴，除了内维度匹配，还必须符合 NumPy 的批次广播规则。本辅助函数只检查代码中覆盖的情况，其余不兼容情况仍可能由后续 `np.matmul` 报错。

把检查和计算分开，便于分别理解：`_validate_matmul_shapes` 负责输入规则，`matmul` 负责具体算法。

### 🧪 单元测试：矩阵乘法

输入校验由 `_validate_matmul_shapes` 负责后，这组测试集中核对 `matmul` 的数值结果，包含方阵、长方形矩阵以及矩阵乘向量的情况。

**检查内容**：不同形状组合下的矩阵乘法，以及 `@` 运算符。  
**为什么要检查**：线性代数计算和数据变换都依赖这个核心操作。  
**预期结果**：与手工逐项计算点积得到的数值一致。

“方阵”表示行数与列数相等，例如 `(2, 2)`；“矩阵乘向量”把每一行与同一个向量做点积，例如 `(2, 3) @ (3,)` 得到形状为 `(2,)` 的结果。`a @ b` 是调用相应矩阵乘法接口的简洁写法。

## 🏗️ 形状操作：重塑与转置

数据处理时，需要把张量的形状调整为下一步运算所要求的形式。理解每条轴的含义，比只记住形状数字更重要。

### 为什么经常需要调整形状？

下面是一条典型的图像处理流程，重点观察样本轴、通道轴与空间轴：

```
一批 RGB 图像：(32, 3, 224, 224)
# 32 张图像，红绿蓝 3 个通道，每张图像高 224、宽 224
     ↓ 经过特征提取等空间计算
中间特征：(32, 512, 7, 7)
# 每张图像对应 512 个特征通道，每个通道是 7×7 的网格
     ↓ 对高、宽两个空间轴求平均
汇总特征：(32, 512)
# 每张图像对应 512 个汇总特征
     ↓ 与形状为 (512, 10) 的矩阵相乘
最终输出：(32, 10)
# 每张图像得到 10 个输出值
```

RGB 表示红、绿、蓝三个颜色通道；通道可以理解为“同一位置不同种类的数据”。这些步骤会涉及形状变化，但特征提取、求平均和矩阵乘法还会计算新数值，不能用 `reshape` 代替。

### 重塑：保持元素顺序，改变分组方式

重塑（reshape）在保持元素总数的前提下，为数据指定新形状。

```
原数据：[1, 2, 3, 4, 5, 6]    形状为 (6,)
          ↓ reshape(2, 3)
结果： [[1, 2, 3],             形状为 (2, 3)
        [4, 5, 6]]

按默认的 C 顺序观察元素序列：
重塑前：1 → 2 → 3 → 4 → 5 → 6
重塑后：1 → 2 → 3 → 4 → 5 → 6
```

可以把它想成把 6 张按顺序排好的卡片，重新分成“2 行，每行 3 张”。`reshape(3, 2)` 也可以，因为 `3 × 2 = 6`；`reshape(4, 2)` 不行，因为新形状需要 8 个元素。

**视图与副本**：

- **视图（view）**：多个数组对象共享同一块底层数值存储，只用不同的形状、步长等元信息解释数据。
- **副本（copy）**：有自己独立的数据存储，创建时通常需要复制元素。
- NumPy 的 `reshape` 在条件允许时返回视图，否则可能复制；不能对所有数组一概承诺零拷贝。
- **本章 `Tensor.reshape` 会把结果传入 `Tensor(...)`，构造器又用 `np.array` 创建副本，因此本接口不保证共享内存，也不能直接称为 O(1) 的零拷贝操作。** 本类的 `view()` 是 `reshape()` 的别名，同样受此影响。

| 常见需求 | 形状示例 | 含义 |
|---|---|---|
| 展平每条样本 | `(N, H, W, C) → (N, H×W×C)` | 把每张图的所有位置和通道合成一条特征向量 |
| 恢复多维分组 | `(N, D) → (N, H, W, C)` | 要求 `D = H×W×C` |
| 增加批次轴 | `(H, W) → (1, H, W)` | 把一个二维对象表示成“只有一条样本的一批数据” |
| 矩阵展平成向量 | `(H, W) → (H×W,)` | 从二维变为一维，数值顺序不变 |

这些符号中，`N` 表示样本数，`H`、`W` 表示高和宽，`C` 表示通道数。`(N, H, W, C)` 与前面的 `(N, C, H, W)` 使用了不同的轴顺序，不能只靠 `reshape` 就保证把两种布局正确互换。

### 转置：交换轴

转置（transpose）改变轴的顺序。二维矩阵转置就是交换行和列：

```
原矩阵：[[1, 2, 3],          形状为 (2, 3)
         [4, 5, 6]]
          ↓ transpose()
转置后：[[1, 4],             形状为 (3, 2)
         [2, 5],
         [3, 6]]

转置前按行读到：1, 2, 3, 4, 5, 6
转置后按行读到：1, 4, 2, 5, 3, 6
```

这两行序列说明的是**逻辑访问顺序**，不能据此断言物理内存已经重排。NumPy 的转置通常通过交换形状和**步长（stride）**来创建视图：步长表示沿某条轴前进一步，在内存地址上应移动多少字节。例如按行连续存储的 `float32` 二维数组中，向右一个元素通常移动 4 字节。

本章将转置结果重新包装为 `Tensor`，会复制数值；复制后具体采用怎样的连续布局，要查看数组实际的步长与标志，不能照搬“NumPy 转置总是共享原内存”的结论。

**`reshape` 与 `transpose` 的区别**：上面的数据 `reshape(3, 2)` 得到 `[[1, 2], [3, 4], [5, 6]]`；转置得到 `[[1, 4], [2, 5], [3, 6]]`。虽然结果形状都是 `(3, 2)`，元素位置不同。

本类 `transpose()` 默认只交换最后两条轴；显式指定时，需要同时提供 `dim0` 和 `dim1`。不要把二维情况下的行列交换，直接理解成多维数组所有轴都会倒过来。

| 应用场景 | 转置参与的计算 | 初学者需要知道的前提 |
|---|---|---|
| 协方差矩阵 | `X.T @ X` | 若行表示样本，应先按特征中心化，并按约定除以样本数或样本数减一；单独这个乘积不是已归一化的相关系数矩阵 |
| 最小二乘 | `A.T @ A` 与 `A.T @ b` | 常用于推导正规方程；`A.T @ b` 本身不是把 b 投影到 A 列空间后的完整结果 |
| 数据排列 | 交换行列或其他两条轴 | 让下一步运算能在正确的轴上读取数据 |

表格中的 `X.T`、`A.T` 沿用 NumPy 的转置记号；本章 `Tensor` 没有 `.T` 属性，实际应写作 `X.transpose()`、`A.transpose()`。

“最小二乘”是寻找一组参数，让预测与真实值之间的平方误差总和尽可能小；这里先知道转置为什么会出现在公式中即可。

### 性能影响：区分底层数组与本章包装

| 接口 | 典型 NumPy 行为 | 本章 Tensor 的额外行为 |
|---|---|---|
| `reshape()` | 可能只改变元信息，也可能复制 | 包装结果时创建数组副本 |
| `transpose()` | 通常调整轴与步长，产生视图 | 包装结果时创建数组副本 |
| `view()` | 此处是 Tensor 的接口名 | 调用本章的 `reshape()`，不是零拷贝承诺 |

只改元信息的数组视图通常可以用很小的固定开销创建；复制包含 `n` 个元素的数据则需要随 `n` 增长的时间与空间。对于本章的接口，不能把“1000×1000 的矩阵操作约为 0.001 毫秒”当作固定性能结论，应在实际环境中测量。

另外，要分清“创建转置结果的时间”与“后来遍历该结果的时间”。在按行访问不连续视图时，缓存复用可能较差；但速度取决于轴、步长、布局和后续算法，不能笼统断言转置必然更慢或无法并行化。

完整框架经常尽量用形状和步长描述变换，把真正的数据搬移推迟到需要连续存储时。这有助于理解常见优化思路；判断本章是否复制，仍应以构造器和方法的实际代码为准。

- **测试内容**：重塑、自动推导一个维度、转置，以及错误处理。
- **为什么要测试**：处理图片或一批数据时，形状错误往往会让后续计算失败。

## 🏗️ 归约操作：把一组数汇总成结果

**归约（reduction）**就是把多个数按某种规则汇总，例如求和 `sum`、平均值 `mean`、最大值 `max`。
它常用于统计特征、计算平均损失，以及对图像区域做汇总。
损失可以先理解为“模型预测与正确答案相差多少”的一个分数。

### 为什么机器学习需要归约

假设成绩表的每行是一名学生，每列是一门学科：

| 目标 | 操作 | 输入形状 → 输出形状 |
|---|---|---|
| 每门学科的平均分 | `grades.mean(axis=0)` | `(N, D) → (D,)` |
| 每名学生的平均分 | `grades.mean(axis=1)` | `(N, D) → (N,)` |
| 每张灰度图的平均像素值 | `images.mean(axis=(1, 2))` | `(N, H, W) → (N,)` |

这里 `N` 是样本数量，`D` 是特征或学科数量，`H` 和 `W` 是图像的高和宽。
**特征（feature）**指描述一个样本的某项数值，比如身高、体重或一个像素的亮度。
**池化（pooling）**可以理解为“用区域内的一个代表值概括这个区域”；对整张图求平均是一种全局平均池化。

### 如何理解 axis（轴）

轴从 `0` 开始编号。`axis` 指定的是“沿哪个轴合并数值”。
默认 `keepdims=False` 时，该轴会从结果形状中消失；没有指定 `axis` 时，汇总全部元素。

```text
原矩阵：[[1, 2, 3],
         [4, 5, 6]]    形状 (2, 3)

axis=0：合并两行，同一列的数放在一起计算。
         1+4   2+5   3+6  → [5, 7, 9]，形状 (3,)

axis=1：合并每行内的三列，每行各得到一个结果。
         1+2+3 → 6
         4+5+6 → 15       → [6, 15]，形状 (2,)
```

| 操作 | 结果 | 含义 |
|---|---|---|
| `.sum()` | `21` | 六个数的总和，结果形状 `()` |
| `.sum(axis=0)` | `[5, 7, 9]` | 每列一个和 |
| `.sum(axis=1)` | `[6, 15]` | 每行一个和 |
| `.mean()` | `3.5` | `21 / 6` |
| `.mean(axis=0)` | `[2.5, 3.5, 4.5]` | 每列一个平均值 |
| `.max()` | `6` | 最大的数值；不是该数的位置 |

**记忆方法**：形状 `(2, 3)` 中，去掉第 `0` 个轴，剩下 `(3,)`；去掉第 `1` 个轴，剩下 `(2,)`。
“沿第 0 轴求和”虽然合并的是行，最终得到的却是“每列的和”，这里最容易混淆。

```text
三维数据形状：(2, 3, 4) = (样本数, 高, 宽)

.sum(axis=0)      → (3, 4)  # 合并样本轴，相同像素位置相加
.sum(axis=1)      → (2, 4)  # 合并高度轴
.sum(axis=2)      → (2, 3)  # 合并宽度轴
.sum(axis=(1, 2)) → (2,)    # 同时合并高、宽，每张图得到一个总和
```

### keepdims：为什么要保留长度为 1 的轴

`keepdims=True` 的含义是“汇总后仍保留这个轴，只把它的长度变成 1”。
例如 `(2, 3)` 按 `axis=1` 求和：默认结果为 `(2,)`，保留轴后为 `(2, 1)`。

```python
x = Tensor([[1, 2, 3], [4, 5, 6]])
row_mean = x.mean(axis=1, keepdims=True)  # [[2.], [5.]]，形状 (2, 1)
centered = x - row_mean                 # 每行减去自己的均值，形状仍是 (2, 3)
# centered.data 为 [[-1., 0., 1.], [-1., 0., 1.]]
```

长度为 `1` 的最后一轴可以广播到 `3`。若均值形状是 `(2,)`，从右对齐时 `2` 与 `3` 不匹配，就无法完成这个减法。
`keepdims` 解决的是形状兼容问题，本身不保证计算更快。

### 内存和性能：先保证含义正确，再测量速度

设输入共有 `E` 个元素，以下完整归约都需要读取这些元素，计算量通常为 `O(E)`。
`O(E)` 表示元素数翻倍时，基本计算量大致翻倍，不代表每次运行的毫秒数完全成比例。

| 操作 | 计算量 | 理解内存访问时要注意什么 |
|---|---|---|
| `.sum()`、`.mean()`、`.max()` | `O(E)` | 需要读取全部元素；布局会影响读取方式 |
| `.sum(axis=0)` | `O(E)` | 按行连续存储时，逐列遍历可能有较大步长 |
| `.sum(axis=1)` | `O(E)` | 按行连续存储时，一行内的元素相邻 |

**步长（stride）**是沿某个轴移动一个位置时，内存地址跨过的字节数。
**缓存局部性（cache locality）**是指程序是否经常使用刚读过或相邻的数据；这样更有机会从速度较快的 CPU 缓存读取。
按行连续存储时，逐列访问可能降低局部性，也可能让一次处理多个数的向量化优化更困难。

但不能断言 `axis=0` 一定更慢：NumPy 的归约实现会优化遍历方式，实际结果还受形状、数据布局、硬件和缓存状态影响。
在数学含义允许时，可以研究最后一轴 `axis=-1` 的归约、调整布局或预先整理数据，再比较总耗时。
单纯 `reshape` 不会自动让所有计算更快，本教材重新包装 Tensor 还有复制成本。

## 📊 系统分析：内存布局与运行速度

下面集中观察一个问题：**同样是求和，逐行访问与逐列访问为什么可能耗时不同？**

把主内存想成存放大量数据的书架，把 CPU 缓存想成手边的小桌子。
一次拿来相邻的一小段数据后，如果接下来正好继续使用它们，就能减少重复去书架取数据的次数。
硬件按“缓存行”搬运数据；常见缓存行大小为 64 字节，可容纳 16 个 `float32` 数值，具体大小取决于硬件。

实验创建一个 `(2000, 2000)` 的矩阵：逐行求和时，同一行的数相邻；逐列求和时，相邻两行的同列元素相隔 `2000 × 4 = 8000` 字节。
这可以帮助理解访问模式，但耗时也包含 Python 循环和函数调用的成本。

**如何正确解读下面的输出**：

- `col_time / row_time` 是本次“逐列求和耗时 ÷ 逐行求和耗时”。大于 1 才表示此次逐列更慢。
- 示例只各计时一次，没有直接测量缓存未命中次数；输出中把耗时差全部归因为缓存的句子，是简化教学说法，不能当作严格测量结论。
- 逐列访问并不等于每次都必须从 DRAM（主内存）读取，缓存层级、预取和矩阵大小都会影响结果。
- 这里没有计时 `transpose()`，因此输出中的耗时倍率不能用于判断转置有多慢。
  本 Tensor 的转置还会通过构造器复制数组，具体布局可查看 `data.flags`，不能直接套用 NumPy 视图的零拷贝结论。
- 输出沿用原代码的 `MB` 标签，但除数是 `1024 × 1024`，严格单位为 MiB。

以后做性能比较时，可先预热、重复多次、比较中位数，并保持输入规模一致。
矩阵乘法的分块（tiling）优化也是为了让一小块数据留在缓存里反复使用，减少搬运。

## 🔧 综合应用：把基础操作组合起来

单个方法通过测试之后，还需要验证它们组合起来能否完成实际计算。

### 从线性变换到仿射变换

机器学习中常见的公式是 **`y = xW + b`**。
`xW` 是线性变换；再加上偏置 `b` 后，更准确的名称是**仿射变换（affine transformation）**。

- **输入 `x`**：每行一个样本，每列一个特征。
- **权重 `W`**：决定输入各项对输出的影响程度。这里由我们指定数值，以后的训练会调整这些参数。
- **偏置 `b`**：为每个输出增加一个常量，就像把一条直线整体向上或向下平移。
- **批次（batch）**：一次放在一起处理的多个样本；每个样本使用同一组权重和偏置。

```text
输入 x           权重 W                偏置 b
(批次, 输入特征) @ (输入特征, 输出特征) + (输出特征,)
                         ↓
                 输出 y：(批次, 输出特征)
```

| 步骤 | 对象 | 形状 |
|---|---|---|
| 1 | 输入 `x` | `(batch_size, input_features)` |
| 2 | 权重 `W` | `(input_features, output_features)` |
| 3 | 矩阵乘法 `xW` | `(batch_size, output_features)` |
| 4 | 偏置 `b` | `(output_features,)`，广播到每一行 |
| 5 | 结果 `xW + b` | `(batch_size, output_features)` |

手算一个“两条样本、每条三个特征、输出两个特征”的例子：

```text
x = [[1, 2, 3],     W = [[0.1, 0.2],     b = [0.1, 0.2]
     [4, 5, 6]]          [0.3, 0.4],
                        [0.5, 0.6]]

第一步：矩阵乘法，每个位置都做“对应相乘，再相加”。
xW = [[1×0.1+2×0.3+3×0.5, 1×0.2+2×0.4+3×0.6],
      [4×0.1+5×0.3+6×0.5, 4×0.2+5×0.4+6×0.6]]
   = [[2.2, 2.8],
      [4.9, 6.4]]

第二步：每行加同一个偏置 [0.1, 0.2]。
y = [[2.3, 3.0],
     [5.0, 6.6]]
```

### 这个组合说明了什么

矩阵乘法把输入特征组合成新的特征；广播让每个样本都加上同一个偏置；形状检查保证这些操作能够衔接。
各操作返回新 Tensor，因此这些计算不会覆盖输入中的数值。

后面的综合测试会连续做两次仿射变换，验证数据能够逐步流动。
**初学者补充**：如果两次变换之间没有非线性激活函数，它们仍能合并成一次仿射变换。
下一模块的激活函数会引入非线性，让网络能够表达更复杂的关系。

## 🤔 机器学习系统思考题

完成 Tensor 后，还要练习估算：数据占多少内存？计算量怎样增长？代码为什么可能受硬件影响？
先自己思考，再阅读提示。这里的估算不要求你已经掌握 GPU 编程。

### 问题 1：存储顺序如何影响缓存

按行存储（row-major）与按列存储（column-major），会如何影响张量操作的运行速度？

思考以下情况：

- 连续访问相邻数字，与每次跨很远读取一个数字，缓存利用率有什么区别？
- 如果实验中逐列访问更慢，能否结合当前按行连续的布局解释一种可能原因？
- 图片处理经常按什么顺序读取像素？怎样让存储布局适合这种顺序？

**提示**：库会选择适合常见访问方式的布局，以提高缓存局部性。
“逐行更快”取决于数据当前的布局；按列连续存储时，应重新分析，不能死记结论。

### 问题 2：批次大小翻倍会发生什么

计算 `y = xW + b` 时，如果样本数翻倍，内存和耗时各会怎样变化？

以 `(32, 784) @ (784, 256)` 改为 `(64, 784) @ (784, 256)` 为例：

- 输入 `x` 的元素数翻倍，输出 `y` 的元素数也翻倍。
- 权重 `W` 与偏置 `b` 由所有样本共用，大小不变；因此总内存通常不会恰好翻倍。
- 标准矩阵乘法的基本计算量约为 `2 × 批次大小 × 输入特征数 × 输出特征数`，所以计算量约翻倍。

**提示**：若原来耗时 10 毫秒，把新耗时估为 20 毫秒可以作为粗略起点，但实际不一定是 20 毫秒。
并行程度、缓存、库实现与固定调用开销都会影响结果；当前二维实现还有 Python 循环成本。

### 问题 3：数值精度与内存有什么关系

一个 `(1000, 1000)` 的数组，使用 `float64` 与 `float32` 时分别占多少数据内存？

```text
元素数 = 1000 × 1000 = 1,000,000
float64：每个数 8 字节，共 8,000,000 字节 = 8 MB，约 7.63 MiB
float32：每个数 4 字节，共 4,000,000 字节 = 4 MB，约 3.81 MiB
```

这里 `MB` 按十进制（1,000,000 字节）计算，`MiB` 按二进制（1,048,576 字节）计算。
当前 Tensor 构造器固定使用 `float32`；上述 `float64` 数值是用于比较的估算。

**提示**：`float16` 与 `bfloat16` 都是每元素 2 字节；相对 `float32`，数据内存减半，
相对 `float64` 则降到四分之一。
位数减少通常会影响能表示的精度或数值范围，两种 16 位格式的取舍也不同。
例如只有 8～16 GB 显存的设备，更需要仔细安排数据类型；实际 GPU 的显存容量各不相同。

### 问题 4：大模型的权重需要多少内存

一个模型有 1750 亿个参数，仅用 `float32` 存储这些权重，需要多少内存？

```text
参数数量：175 × 10^9
每个参数：4 字节
权重数据：700 × 10^9 字节 = 700 GB，约 652 GiB
```

**参数**就是模型里可以被训练调整的数字，如前面的 `W` 和 `b`。
**提示**：这里只算权重。训练时还可能需要梯度、优化器状态和中间结果，因此总内存会更大。
梯度可以先理解成“参数改变一点时，损失大约会怎样变化”的信息，后续模块再深入学习。

### 问题 5：为什么常把许多小计算合成一批

比较下面两种处理方式：

- 方式 A：分别发起 1000 次 `(10, 10) @ (10, 10)`。
- 方式 B：把两组矩阵都组织成 `(1000, 10, 10)`，做一次批量矩阵乘法，逐对计算这 1000 组矩阵。

**提示**：准备和启动计算本身也要花时间，好比每次寄快递都要填单。
把任务合成一批，可以分摊固定开销，让并行处理器有更多工作可同时执行。
GPU 启动开销有时可在几微秒量级（如 5～10 微秒），但这只是帮助理解的数量级，实际值取决于平台。
本模块使用 NumPy 在 CPU 上计算，没有实现 GPU 调度；批量处理也应通过实测确认是否获益。
