## 💡 入门：什么是损失函数？

损失函数比较模型预测与真实标签，好比训练时的记分员：模型需要明确的目标，才能知道调整是否有帮助。这里的“距离”是直观比喻，交叉熵并不满足数学距离的全部性质。

### 三种基本损失

**均方误差 MSELoss**回答：“连续数值预测偏离了多少？”

- 用于回归，例如房价、温度、股票价格预测。
- 先计算每个预测与目标之差的平方，再平均。
- 对大误差惩罚较重，关于预测的导数连续。

```text
平方误差曲线：
  损失 ↑       *       *
    4  |       |       |
    1  |         *   *
    0  |___________*________→ 预测误差
              -2 -1 0 1 2
误差平方增长：小误差惩罚小，大误差惩罚更重。
```

**交叉熵 CrossEntropyLoss**回答：“模型给真实类别的概率有多低？”

- 用于单标签多分类，例如图像识别、文本分类。
- 计算真实类别概率的负对数，即负对数似然（negative log-likelihood）。
- 真实类别概率越高损失越低；把错误类别判断得很有把握时，真实类别概率低，损失大。

```text
真实类别概率 p：  0.001   0.01   0.1    0.5    1.0
损失 -log(p)：   6.908   4.605  2.303  0.693  0
曲线沿概率轴向右下降；p 趋近 0 时，损失趋向无穷大。
```

**二元交叉熵 BinaryCrossEntropyLoss**回答：“这个是／否判断错了多少？”

- 用于垃圾邮件检测、疾病预测等二分类任务。
- 是两类别交叉熵的专门写法。
- 在交换正负标签并把概率改为 `1-p` 后，损失相同；这不意味着自动解决类别数量不平衡。

| 预测概率的极限 | 目标为 1（正类） | 目标为 0（负类） |
|---|---|---|
| `p → 1` | 损失 → 0 | 损失 → ∞ |
| `p → 0` | 损失 → ∞ | 损失 → 0 |

表格描述理想公式；本实现会裁剪概率，因此端点返回有限值。三种损失形成不同的误差曲面，引导模型以不同方式改进。

## 📐 基础：数学背景

### 均方误差 MSE

```text
MSE = (1/N) × Σ(预测值_i - 目标值_i)²
```

这里 `N` 是参与平均的**全部元素数**。例如 `(批大小 B, 输出数 D)` 的输入有 `B×D` 个元素，分母不是只有 `B`。

为什么平方？平方让正负误差不互相抵消；误差 2 变成 4、误差 10 变成 100，突出较大偏差；平方函数有平滑导数，便于优化。误差为零时平方仍为零，所以严格说是“非负”。

### 交叉熵

对一个样本，若目标分布为 `y`、预测概率为 `p`：

```text
交叉熵 = -Σ_i y_i × log(p_i)
```

单标签分类中，真实类别位置为 1，其他位置为 0，这个式子化为 `-log(p_真实类别)`。本地接口使用类别编号，内部由原始得分 logits 计算对数概率，再对批次求均值。

**log-sum-exp 稳定技巧**：直接对很大的数求指数可能溢出。

```text
log_softmax(x)_i = x_i - log(Σ_j exp(x_j))
                 = x_i - m - log(Σ_j exp(x_j - m))，m = max(x)
```

减去同一个最大值不会改变 softmax 概率，却让指数的输入不大于 0，避免正向指数溢出。

### 二元交叉熵 BCE

```text
BCE_单元素 = -[y × log(p) + (1-y) × log(1-p)]
```

`y=1` 时只保留 `-log(p)`，`y=0` 时只保留 `-log(1-p)`，一个公式涵盖正负两类。本实现最后对全部元素求平均。

## 🏗️ 实现：构建损失函数

实现时同时关注数学公式、数值稳定性与清晰的数据形状。

### Log-Softmax：分类损失的稳定基础

logits 是尚未归一化的模型得分，可以为负，也不要求和为 1；softmax 把这些得分变为概率，而 log-softmax 直接得到概率的对数。

```text
朴素路径：
logits = [100, 200, 300]
exp(300) ≈ 1.94 × 10^130 → 超出 float32 的范围

稳定路径：
最大值 = 300
平移后 = [-200, -100, 0]
最大指数项 exp(0) = 1，便于表示
```

`exp(300)` 仍能用 float64 表示；这里风险来自本 Tensor 使用 float32，而不是所有计算机都无法表示它。

```text
原始计算                          稳定计算
得分 [a,b,c]                      得分 [a,b,c]
    ↓                                 ↓
求 exp(得分)                       m = max(a,b,c)
    ↓                                 ↓
指数求和                           平移为 [a-m,b-m,c-m]
    ↓                                 ↓
对总和求 log                       求 exp(平移值)，每项 ≤ 1
    ↓                                 ↓
得分减去 log(总和)                 指数求和，再求 log
                                      ↓
                                  得分 - m - log(总和)
```

在精确算术中两式等价。稳定形式避免了大正数的指数溢出，但不能保证任意输入安全：NaN、无穷大、超出数据类型范围的输入或极端差值仍需检查。

#### 🧪 单元测试：Log-Softmax

本测试检查数值正确性与稳定性。

**检查内容**：输入输出形状一致，`exp(log_softmax)` 沿类别轴求和接近 1，大值输入的结果没有 NaN 或无穷大。  
**作用**：交叉熵依赖这一基础操作，因此先单独核对。  
**预期**：测试覆盖的输入得到有限结果，归一化概率和为 1；这不是对所有极端浮点输入的保证。

### MSELoss：衡量连续数值预测质量

均方误差是回归任务常用的目标，衡量连续预测与真实值之间的平方偏差。

#### 适用场景

- 房价预测，例如 20 万美元与 19.5 万美元。
- 温度预报，例如 25°C 与 23°C。
- 股票价格预测，例如 150 美元与 148 美元。
- 其他“数值偏离多少”有意义的任务。

#### MSE 如何影响学习

```text
目标值 = 100
预测值： 80   90   95   100  105  110  120
误差：  -20  -10   -5     0   +5  +10  +20
平方误差：400 100   25     0   25  100  400

损失曲线呈 U 形，最低点位于预测值 100。
左右偏差相同，损失相同；偏差翻倍，平方误差变为四倍。
```

平方有四点意义：`(-10)²=(+10)²=100`，误差不会抵消；误差 20 的惩罚是 400；二次函数导数连续；若假设误差为独立同方差高斯噪声，最小化 MSE 对应最大似然估计。

#### 与其他回归损失比较

| 误差 | -10 | -5 | 0 | +5 | +10 |
|---|---:|---:|---:|---:|---:|
| 平方误差 MSE 的单元素项 | 100 | 25 | 0 | 25 | 100 |
| 绝对误差 MAE 的单元素项 | 10 | 5 | 0 | 5 | 10 |
| Huber，阈值 δ=1 | 9.5 | 4.5 | 0 | 4.5 | 9.5 |

MSE 二次增长，对离群点敏感；MAE 线性增长，通常更稳健；Huber 在 `|误差|≤δ` 时用 `0.5×误差²`，超过阈值时用 `δ×(|误差|-0.5δ)`，兼顾近零平滑和远处线性。原教材未给阈值的 Huber 数值不能确定具体定义，这里明确采用 δ=1。Huber 只是延伸比较，本章并未实现。

**小练习**：把所有目标和预测同时乘以 100，MSE 会乘以 10,000；这说明不同单位下的 MSE 不能直接比较。

#### 🧪 单元测试：均方误差

检查完全正确的预测、已知误差和随机输入。

**检查内容**：完全匹配时损失为 0；示例手算值为 0.18；随机输入的结果非负。  
**作用**：回归依赖正确的平均与平方计算。  
**预期**：有误差时为正，无误差时为零。调用方还应保证形状一致，避免 NumPy 把 `(B,1)` 与 `(B,)` 意外广播成 `(B,B)`。

### CrossEntropyLoss：衡量分类预测的把握程度

交叉熵是单标签多分类常用的目标；它衡量真实类别被分配了多大的概率，并惩罚很有把握的错误判断。

#### 适用场景

图像分类（猫、狗、鸟）、文本分类（垃圾邮件、普通邮件、促销邮件）、语言模型的下一个词元预测，以及类别互斥、每个样本只有一个正确类别的问题。

#### 三个具体例子

```text
场景：图像分类，类别顺序为 [猫, 狗, 鸟]

情形一：正确且有把握
原始得分：[5.0, 1.0, 0.1]
softmax 概率约为：[0.9749, 0.0179, 0.0073]
真实标签：猫，类别 0
损失约为 -log(0.9749) = 0.0254 → 很低

情形二：正确但不确定
原始得分：[1.1, 1.0, 0.9]
softmax 概率约为：[0.3672, 0.3322, 0.3006]
真实标签：猫，类别 0
损失约为 -log(0.3672) = 1.0019 → 更高

情形三：错误且有把握
原始得分：[0.1, 5.0, 1.0]
softmax 概率约为：[0.0073, 0.9749, 0.0179]
真实标签：猫，类别 0
损失约为 4.9254 → 很高
```

上述数值按实际 softmax 重新核算，避免把不对应这些 logits 的概率当成计算结果。

#### 损失提供什么学习信号

| 预测把握程度 | 是否正确 | 直观反馈 |
|---|---|---|
| 高 | 正确 | 继续保持真实类别的高概率 |
| 低 | 正确 | 增加真实类别的概率 |
| 高 | 错误 | 明显降低错误偏好，提高真实类别概率 |
| 低 | 错误 | 学习正确类别，提高其概率 |

```text
真实类别概率：  0.001  0.01   0.1   0.5    1
损失：          6.91   4.61   2.30  0.69   0
曲线不断下降：给正确类别更高概率，会降低损失。
```

它有概率解释，可衡量预测分布；自信的错误产生大损失；对有限 logits，稳定表达式可平滑优化；从信息论看，它减少真实答案带来的“意外程度”。大损失不等于对 logits 的梯度无限大，也不能保证快速收敛。

#### 多分类与二分类

| 项目 | 多分类示例 | 二分类示例 |
|---|---|---|
| 类别 | 猫、狗、鸟 | 垃圾邮件、普通邮件 |
| 概率表示 | `[0.7,0.2,0.1]`，总和为 1 | `0.8`，表示垃圾邮件概率 |
| 本地接口 | `CrossEntropyLoss` 接收未 softmax 的 logits | `BinaryCrossEntropyLoss` 接收 `[0,1]` 概率 |

二分类也可以用两个 logits 配合交叉熵。不要把概率再传入本地 CE 做第二次 softmax；标签使用 `(B,)` 类别编号，不是 one-hot 数组。

#### 🧪 单元测试：交叉熵

测试正确且有把握、均匀不确定、错误且有把握以及大 logits 四种输入。

**作用**：分类损失需要在不同概率分布下给出一致的目标。  
**预期**：正确高置信预测损失低；错误高置信预测损失高；三个类别均匀预测时损失约为 `log(3)=1.099`；测试中的大 logits 计算保持有限。

### BinaryCrossEntropyLoss：衡量是／否判断的质量

二元交叉熵是两类别情况下交叉熵的专门形式。常见任务包括垃圾邮件检测、疾病预测、欺诈识别、内容审核，以及其他二选一判断。

#### 从混淆矩阵理解 BCE

| 模型判断 | 真实正类 | 真实负类 |
|---|---|---|
| 判断为正类“是” | 真阳性 TP，`-log(p)` | 假阳性 FP，`-log(1-p)` |
| 判断为负类“否” | 假阴性 FN，`-log(p)` | 真阴性 TN，`-log(1-p)` |

同一行公式的选择由真实标签决定；TP/TN 概率判断越有把握，损失越低；FP/FN 越有把握地判断错误，损失越高。这里的阈值判断用于解释，实际 BCE 直接使用连续概率。

#### 垃圾邮件例子

```text
情形一：正确识别垃圾邮件
邮件：“立即购买！五折优惠！限时抢购！”
p=0.99，真实标签 y=1
损失=-log(0.99)≈0.0101 → 很低

情形二：不确定
邮件：“会议改到下午两点”
p=0.51，真实标签 y=0
损失=-log(0.49)≈0.7133 → 中等

情形三：很有把握地判断错误
邮件：“妈妈，你最近好吗？”
p=0.95，真实标签 y=0
损失=-log(0.05)≈2.9957 → 较高
```

#### 二元交叉熵与多分类交叉熵

| 项目 | 二元交叉熵 | 多分类交叉熵 |
|---|---|---|
| 概率表示 | 单个正类概率，如 0.8 | 多类别分布，如 `[0.1,0.8,0.1]` |
| 目标 | 0 或 1 | 类别编号，如 1 |
| 单样本公式 | `-[y*log(p)+(1-y)*log(1-p)]` | `-log(p[真实类别])` |
| 本地实际输入 | 概率 | 原始 logits，内部计算 log-softmax |
| 类别不平衡 | 通常需权重、重采样等额外策略 | 同样可能需要额外策略 |

普通 BCE 不会自动平衡类别，普通 CE 也不要求类别必须均衡；是否偏向多数类与数据、模型和优化目标共同有关。

#### 二元写法的特点

1. 交换正负类与相应概率时公式对称，但业务中漏报和误报代价可以不同。
2. 输入具有概率语义；是否校准良好仍须独立评估。
3. 一个概率即可表示两类分布，通常比显式建立两列概率更简洁。
4. 可用于医疗等二分类研究，但仅选择 BCE 不能证明系统满足临床或安全要求。

#### 损失曲线

```text
预测 p：     0.01   0.2    0.5    0.8    0.99
y=1 的损失： 4.605  1.609  0.693  0.223  0.010
y=0 的损失： 0.010  0.223  0.693  1.609  4.605
```

固定 `y=1` 的曲线从左向右单调下降，固定 `y=0` 则单调上升；不是一条两端都上升的 U 形曲线。目标是提高真实类别概率，而不是奖励“不确定”。

#### 🧪 单元测试：二元交叉熵

测试接近完全正确、接近完全错误、概率均为 0.5，以及概率端点 0 和 1。

**作用**：二分类接口必须处理概率边界。  
**预期**：正确预测损失低，错误预测损失高；0.5 对应 `-log(0.5)≈0.693`；裁剪使边界测试结果有限。

## 🔧 综合应用：把损失与实际问题连接起来

接下来用实际场景比较三种损失，再观察预测变化怎样影响损失。

### 按问题选择损失

```text
要预测什么？
  ├─ 连续数值 → MSELoss
  │             例：房价、温度、股票价格
  └─ 类别
       ├─ 两类 → BCE（也可以使用两个 logits 的 CE）
       │         例：垃圾邮件、欺诈、疾病预测
       └─ 多个互斥类别 → CrossEntropyLoss
                         例：图像类别、语言模型、多分类文本
```

### 误差敏感性比较

损失的输入语义不同，不能拿任意相同数字当作统一的“错误程度”。为了比较，固定二分类真实标签 `y=1`，让概率 `p` 都位于合法范围：

| 真实类别概率 p | 0.9 | 0.5 | 0.01 |
|---|---:|---:|---:|
| 距离 `1-p` | 0.1 | 0.5 | 0.99 |
| 平方误差 | 0.01 | 0.25 | 0.9801 |
| BCE 或相应 CE | 0.1054 | 0.6931 | 4.6052 |

MSE 随数值误差二次增长，因此对离群点敏感；交叉熵在真实类别概率趋近零时变大。概率误差不能为 2；本地 BCE 会裁剪概率，CE 使用稳定 logits 公式，没有采用相同的概率裁剪。

下面敏感性实验让回归预测从 0.1 到 1.9；BCE 分支先裁剪到 `[0.01,0.99]`，所以超过上界后形成平台。网格不一定包含精确的 0.5 或 1.0，打印值取最近采样点，不应当作精确手算值。

## 📊 系统分析：损失计算的性能

损失虽然公式简短，仍会占用计算与临时数组空间。这里用 `B` 表示批大小、`C` 表示类别数。

### 计算复杂度

| 损失／步骤 | 工作量级 |
|---|---|
| 单输出 MSE：减法、平方、均值 | 每一步 `O(B)`，整体 `O(B)` |
| CE：每行最大值、平移、指数、按类别求和 | 每一步 `O(B×C)` |
| CE：对每行指数和取对数、选真实类别、均值 | `O(B)` |
| CE 总计 | `O(B×C)` |

如果 MSE 每个样本也有 `D` 个输出，它是 `O(B×D)`。因此 CE 相比**单输出 MSE**多处理一个类别维度；不能据此断言实际耗时恰好是 `C` 倍，更不能保证 ImageNet 的 1000 类就慢 1000 倍。指数、内存访问、实现和硬件都会影响常数。

### 内存布局与访问

```text
MSE：预测 [B]、目标 [B]
       ↓ 相减
     差值 [B]
       ↓ 平方
     平方差 [B]
       ↓ 平均
     标量 Tensor，形状 ()

CE：logits [B,C]
       ↓ 每行减最大值
    平移数组 [B,C]
       ↓ 求指数、沿 C 求和
    指数临时数组 [B,C]、行和 [B,1]
       ↓ 对行和求 log，再按稳定公式相减
    对数概率 [B,C]
       ↓ 按真实类别索引、取负均值
    标量 Tensor，形状 ()
```

教学估算有时按 MSE 的约 `3B`、CE 的约 `3BC+2B` 个浮点数讨论，但这是选取部分数组的近似口径，不是本实现峰值内存实测。输入目标、构造器复制、临时表达式、对象开销和数组生命周期都可能改变峰值。

下面 `analyze_loss_memory()` 只估计 MSE/BCE 的两份输入，以及 CE 的 logits、目标与一份 `B×C` 中间数组（`2BC+B` 个数），并未实际测量所有临时数组。输出 `MB` 采用十进制 10^6 字节。

数值实验验证有限的测试用例；输出里“任意大的 logits 都安全”是过度概括。float32 的 `exp(700)` 会溢出，而 float64 的同值指数仍可表示，必须注明数据类型。

### 生产环境：损失函数如何随规模增长

分析规模有助于选择架构和训练方案。以下只计算一份 float32 logits 数组，以及单输出 MSE 的一份预测数组，**不是完整损失计算内存**。

| 项目 | 小模型示例 MNIST | 较大视觉模型 ImageNet | 大词表语言模型示例 |
|---|---:|---:|---:|
| 类别数 C | 10 | 1,000 | 50,000 |
| 批大小 B | 64 | 256 | 2,048 |
| CE 一份 logits 字节数 | 2,560（2.56 KB） | 1,024,000（1.024 MB） | 409,600,000（409.6 MB） |
| 单输出 MSE 一份预测字节数 | 256 | 1,024 | 8,192 |
| 可能关注的瓶颈 | 通常很小 | softmax 计算 | 词表相关内存与计算 |

CE 主要数组随 `B×C` 增长。语言模型还需要考虑序列长度，若每个词元均预测，通常相当于增加了参与计算的样本数；大词表可能成为瓶颈，但不代表它总比模型其他部分更昂贵。

### 常见优化及取舍

1. **层次 softmax（hierarchical softmax）**：用树表示类别路径，平衡树下单目标路径长度从 `O(V)` 的全词表计算转为 `O(log V)`。50,000 叶子约需 16 个二叉决策，而非保证仅做 16 次基本运算；模型形式也会改变。
2. **采样 softmax（sampled softmax）**：训练时只选例如 1000 个负类别与真实类别，减少相对 50,000 全类别的候选数。约 50 倍的候选减少不等于保证 50 倍加速，还需考虑采样、校正和近似目标的影响。
3. **标签平滑（label smoothing）**：把 `[0,0,1,0]` 改为 `[0.1,0.1,0.7,0.1]` 一类软分布，减轻过度自信，有时改善泛化。本地 CE 仅接收类别编号，并未实现此接口。
4. **降低精度**：FP16 每数 2 字节，float32 每数 4 字节，可降低数组内存；但指数、归约的稳定性仍需关注，本地 Tensor 构造器目前固定 float32。

后面的输出还举出推荐系统（BCE/MSE，海量交互）、视觉分类（CE，大类别与批次）、翻译（CE，大词表）、医疗预测（BCE，类别不平衡）、价格预测（MSE/Huber，离群点）等场景。权衡包括置信程度与泛化、敏感性与稳健性、完整类别目标与采样效率，以及批次大小与内存。

输出中的“批量快 10～100 倍”“损失耗时低于总训练 5%”均不是本程序测量结果，也不是通用承诺。按样本还是批次计算本身不改变同一均值目标的数学精度；批处理主要分摊调用开销，实际内存峰值可能更大。

### 3. 数值稳定：为什么损失变为无穷大

训练记录如下，原始 logits 出现 `[150,-80,200]`：

```text
第 1 轮：损失 = 2.3
第 2 轮：损失 = 1.8
第 3 轮：损失 = inf
```

为什么可能出现无穷大？可以如何修改？

<details>
<summary>💡 提示</summary>

若用朴素 softmax，`exp(200)≈7.23×10^86` 超出 float32，分子分母可能成为无穷大，进而产生 NaN 或无穷损失；概率下溢为 0 再取 log 也会产生无穷大。

```python
# 朴素形式有溢出或下溢风险。
softmax = np.exp(logits) / np.sum(np.exp(logits))
loss = -np.log(softmax[target])

# 单样本稳定形式；批次版本要沿类别轴归约并保留维度。
log_softmax = logits - np.max(logits) - np.log(np.sum(np.exp(logits - np.max(logits))))
loss = -log_softmax[target]
```

本章的 `CrossEntropyLoss.forward()` 已调用稳定 `log_softmax()`，上面的有限输入本身不会让这个实现失效。若仍异常，应查输入、参数或前序运算是否已经有 NaN/inf、学习率是否过大，以及调用路径是否真的使用稳定实现。概率乘积、极小概率等场景通常适合在对数域计算，但并非所有概率操作都必须改为对数。
</details>

### 4. 实际应用：推理延迟

垃圾邮件过滤器要求少于 10 ms：模型预测 3 ms，额外损失计算 8 ms。代码把阈值传给 BCE 来求“置信程度”：

```python
prediction = model(email)
confidence = bce_loss(prediction, threshold)
```

哪里有问题？

<details>
<summary>💡 提示</summary>

损失用于比较预测与真实标签；阈值不是标签，BCE 也不是置信分数。普通在线分类没有真实标签时，可直接利用模型输出。损失也能用于有标签的离线评估，所以它并非只允许出现在训练阶段。

```python
prediction = model(email)  # 假设返回 [0,1] 概率
is_spam = prediction.data > 0.5

# 这是离阈值距离的启发式分数，不是经过校准的置信概率。
confidence = abs(prediction.data - 0.5) * 2
# 也可直接保留 prediction.data 作为模型输出概率。
```

在给定数字下，移除额外计算后延迟从 11 ms 变为 3 ms，降低约 72.7%。这个数字只来自题设，不是本文件实测。阈值应按误报、漏报代价与验证集选择。
</details>

### 5. 医疗诊断中的类别不平衡

癌症检测数据中 95% 为阴性、5% 为阳性。模型始终预测健康就得到 95% 准确率。有哪些处理方法？

<details>
<summary>💡 提示</summary>

多数类占比让准确率掩盖了所有阳性都被漏掉的问题。

**方法一：加权损失。** 下面是概念示例，`pos_weight=95/5=19` 放大正类项；实际实现应增加概率裁剪与输入验证。

```python
class WeightedBCELoss:
    def __init__(self, pos_weight=19.0):  # 类别比例可作为初始参考
        self.pos_weight = pos_weight

    def forward(self, pred, target):
        loss = -(self.pos_weight * target * np.log(pred) +
                 (1-target) * np.log(1-pred))
        return np.mean(loss)
```

它给正类样本的对数损失 19 倍权重；这不等于任何单个漏诊事件的业务代价一定是误报的 19 倍。

**方法二：焦点损失（focal loss）。** 用 `(1-p_correct)^gamma` 降低容易样本的权重，使训练更关注困难样本；困难样本并不总属于少数类。

```text
focal_loss = -(1-p_correct)^gamma × log(p_correct)
```

**方法三：重采样。** 过采样少数类、欠采样多数类，或在适合的数据上使用 SMOTE（合成少数类过采样）。这些是数据策略，不是损失函数本身。

漏诊与误报的代价须结合具体场景和专业评估，不能仅凭损失类型判断。除准确率外，还应看精确率、召回率、F1、ROC-AUC/PR-AUC 和阈值表现；95% 准确率在此例中缺乏区分能力。上述扩展均未包含在本地 BCE 类中。
</details>

### 6. 批大小与损失计算

GPU 内存 24 GB，批大小 32 时用 8 GB。把批大小改为 128，是否一定需要 32 GB？损失计算耗时、损失数值和误差信号质量怎样变化？

<details>
<summary>💡 提示</summary>

不一定恰好四倍，因为有固定成本。若固定部分 1 GB、随批次变化的部分 7 GB：

```text
原内存 = 1 + 7 = 8 GB
新内存 ≈ 1 + 4×7 = 29 GB
```

这个假设下仍超过 24 GB，但只有题目给出的总内存还不能确定新峰值。模型参数、优化器状态等通常固定，激活与批输入常随批大小增长。

损失运算量约增加四倍；例如 0.5 ms 到 2.0 ms 可作为粗略线性估算，但并行利用率、调用开销和带宽使真实耗时不一定四倍。

采用均值不会因为样本数增加就把损失机械地乘四，但两个批次平均值未必相等：

```python
batch_32_loss = np.mean(losses[:32])
batch_128_loss = np.mean(losses[:128])
```

若从相同分布独立采样，更大批次通常降低估计方差，让损失和梯度较平稳；不保证泛化更好。大批次需更多内存，小批次噪声较大，适合的批大小应依硬件、任务和优化设置实测，64～256 只是可能的尝试范围。

可把多个小批次顺序计算并累积梯度后再更新参数，称为**梯度累积（gradient accumulation）**。要注意正确归一化，且 BatchNorm、随机增强等可能使其不完全等同于一个大批次。
</details>

这些问题关注的不只是公式怎么写，还包括公式放入真实系统后会产生哪些资源成本和诊断线索。
