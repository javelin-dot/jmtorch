# jmtorch 上手指南

这是从零手写迷你 PyTorch 的学习项目。张量、激活函数和网络层等练习位于 `practices/`；后续章节直接复用这些模块，再逐步实现数据加载、自动求导、优化器和训练流程。

对外发行名和导入名都是 `jmtorch`。稳定实现放在 `src/jmtorch/`，测试放在 `tests/`。

## 1. 准备环境

需要 Python 3.10+。所有命令在项目根目录执行。创建并激活虚拟环境后：

```bash
pip install -e ".[dev]"
pytest
python -c "import jmtorch; print(jmtorch.__version__)"
```

Windows PowerShell 可用 `python -m venv .venv` 创建环境，再执行 `.\.venv\Scripts\Activate.ps1`；Linux/macOS 则执行 `source .venv/bin/activate`。

使用 uv 时：

```bash
uv venv
uv pip install -e ".[dev]"
uv run pytest
```

开发依赖包含 NumPy 和 pytest。`pip install -e ".[dev]"` 仅将 `src/jmtorch` 安装为可编辑包，不会把练习包一起发行。版本应输出 `0.1.0`；`jmtorch` 子包仍为等待迁入实现的占位。

## 2. 目录与学习顺序

| 路径 | 用途 |
| --- | --- |
| `practices/` | 可互相导入的练习模块，文件名不含章节数字 |
| `practices/guides/` | 按章节编号组织的练习说明 |
| `src/jmtorch/` | 可安装的正式库，稳定接口迁入这里 |
| `tests/` | 包导入、练习复用与各阶段行为测试 |
| `scripts/` | 训练和导出入口占位 |
| `docs/zh/` | 中文学习材料 |

| 顺序 | 练习文件 | 对应正式库 |
| --- | --- | --- |
| 01 张量 | `practices/tensor.py` | `src/jmtorch/tensor/` |
| 02 激活函数 | `practices/activations.py` | `src/jmtorch/nn/` |
| 03 网络层 | `practices/layers.py` | `src/jmtorch/nn/` |
| 04 损失函数 | `practices/losses.py` | `src/jmtorch/nn/` |
| 05 数据管道 | `practices/data.py` | `src/jmtorch/data/` |
| 06 自动求导 | `practices/autograd.py` | `src/jmtorch/autograd/` |
| 07 优化器 | `practices/optim.py` | `src/jmtorch/optim/` |
| 08 训练循环 | `practices/training.py` | `src/jmtorch/training/` |
| 09 导出 | `practices/export.py` | `src/jmtorch/export/` |

`practices/nn.py` 是网络相关类的集成入口。原先编号目录中的说明已移至 [练习指南](../practices/README.md)，原 `06_autograde` 空目录也合并到 `autograd.py` 对应章节。

先学习张量与前向计算，再为计算过程接入自动求导。后续章节预先导入前面的类或模块，只是准备好复用路径，不表示数据加载、反向传播、优化器和训练已经实现。

## 3. 复用前面章节

在项目根目录运行的脚本或 Python 会话中使用完整包名：

```python
from practices.tensor import Tensor
from practices.activations import ReLU
from practices.layers import Linear

x = Tensor([[1.0, 2.0]])
layer = Linear(2, 3)
y = ReLU()(layer(x))
print(y.shape)
```

在 `practices/losses.py` 等包内模块中使用相对导入：

```python
from .tensor import Tensor
from .activations import ReLU
from .layers import Linear
```

这样不同章节共享同一个 `Tensor` 类，不需要通过文件路径加载模块、修改 `sys.path` 或先迁入正式库才能继续学习。包内运行入口使用 `python -m practices.<模块>`，让 Python 正确建立包上下文。

## 4. 运行与验证

在项目根目录运行已有练习：

```bash
python -m practices.tensor
python -m practices.activations
python -m practices.layers
pytest
```

`layers` 包含性能分析，运行时间相对较长。普通 `import practices.layers` 只加载定义，不执行这些演示。

新增功能时，把真实行为断言写入对应的 `tests/test_<阶段>.py`。可以只运行正在修改的阶段，例如 `pytest tests/test_tensor.py`；失败时加上 `--pdb` 进入调试。空占位测试没有断言，通过并不代表功能已经完成。

排查前向计算时先检查输入、权重和输出的形状，再检查广播语义。实现自动求导后，再检查 `.grad`、计算图和梯度清零；实现数据加载后，检查 batch 形状是否与网络层匹配。

`scripts/run_training.py` 和 `scripts/export_checkpoint.py` 仍是入口占位。完成训练和导出功能后再接入实际实现。

## 5. 迁入正式库与对外使用

练习接口稳定并通过行为测试后，再迁入对应的 `src/jmtorch/` 子包，明确公开导入路径。对外使用 `jmtorch`；仓库内的练习可以继续使用 `practices`，不需要等待所有阶段迁入。

其他项目安装本仓库后：

```bash
pip install -e /path/to/jmtorch
```

使用 `import jmtorch` 及其子包。当前正式库只有版本号和子包占位；`jmtorch.Tensor`、`jmtorch.nn.Linear` 等 API 需要实现并迁入后才可使用。不要把练习目录额外加入其他项目的 `sys.path` 来代替正式库接口。

版本号同时维护在 `pyproject.toml` 与 `src/jmtorch/__init__.py`，当前为 `0.1.0`。

将来 `src/jmtorch/export/` 负责保存与加载权重，`scripts/export_checkpoint.py` 负责命令行入口。保存层权重，加载后验证前向输出一致；不把练习草稿、测试数据或虚拟环境混入导出产物。
