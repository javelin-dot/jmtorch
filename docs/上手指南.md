# jmtorch 上手指南

从零手写迷你 PyTorch 的学习容器。仓库只搭好路径，**没有**现成源码、练习答案或神经网络实现。拿到之后按本文从上往下走即可。

发行名和导入名都是 `jmtorch`。草稿在 `practices/`，稳定代码在 `src/jmtorch/`，断言在 `tests/`。

## 1. 先把环境跑通

需要 Python 3.10+。所有命令都在**仓库根目录**执行。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest
python -c "import jmtorch; print(jmtorch.__version__)"
```

或使用 uv：

```bash
uv venv
source .venv/bin/activate
uv pip install -e ".[dev]"
uv run pytest
```

`pip install -e .` 会按 `pyproject.toml` 把 `src/jmtorch` 装成可编辑包。现在 pytest 只收集 `tests/test_package.py`：能 `import jmtorch`，且 `jmtorch.__version__ == "0.1.0"`。版本号必须与 `pyproject.toml` 里的 `version` 一致。

应打印 `0.1.0`。子包现在也可以导入（`jmtorch.tensor` 等），但里面没有可用的类或函数。环境通了，就可以开始写第一阶段。

## 2. 代码写在哪

本仓库是学习容器。草稿在 `practices/`，稳定代码在 `src/jmtorch/`，断言在 `tests/`。

### 顶层

| 顶层路径 | 用途 |
| --- | --- |
| `src/jmtorch/` | 可安装包（导入名 `jmtorch`）。子包：`tensor`、`autograd`、`nn`、`optim`、`data`、`training`、`export`。 |
| `practices/` | 七个阶段的草稿目录；稳定代码再迁入 `src/`。 |
| `tests/` | 与阶段对应的测试。除骨架冒烟外留空。 |
| `scripts/` | `run_training.py`、`export_checkpoint.py` 入口占位。 |
| `docs/` | 本文（上手指南）。 |
| `pyproject.toml` | 发行名 `jmtorch`，版本 `0.1.0`，可选 `dev`（pytest）。 |

### 每个阶段写三处

| 顺序 | 草稿 | 库实现 | 测试 |
| --- | --- | --- | --- |
| 01 张量 | `practices/01_tensor/` | `src/jmtorch/tensor/` | `tests/test_tensor.py` |
| 02 自动求导 | `practices/02_autograd/` | `src/jmtorch/autograd/` | `tests/test_autograd.py` |
| 03 神经网络 | `practices/03_nn/` | `src/jmtorch/nn/` | `tests/test_nn.py` |
| 04 优化器 | `practices/04_optim/` | `src/jmtorch/optim/` | `tests/test_optim.py` |
| 05 数据管道 | `practices/05_data/` | `src/jmtorch/data/` | `tests/test_data.py` |
| 06 训练循环 | `practices/06_training/` | `src/jmtorch/training/` | `tests/test_training.py` + `scripts/run_training.py` |
| 07 导出 | `practices/07_export/` | `src/jmtorch/export/` | `tests/test_export.py` + `scripts/export_checkpoint.py` |

### 包布局

```
src/jmtorch/
  __init__.py          # 仅 __version__
  tensor/__init__.py
  autograd/__init__.py
  nn/__init__.py
  optim/__init__.py
  data/__init__.py
  training/__init__.py
  export/__init__.py
```

每个子包目前只有模块说明，没有类或函数实现。迁入时保持这个导入路径，方便其他项目 `import jmtorch`。

### 练习目录

每个 `practices/0N_*/` 含：

- `README.md`：本阶段目标与迁入位置
- `practice.py`：空草稿
- `.gitkeep`：保证空目录可被 git 跟踪

不要在练习目录里复制外部实现。写完一阶段并通过测试后，把稳定接口搬进对应的 `src/jmtorch/<子包>/`。

## 3. 按这个顺序做

后一阶段只依赖已经迁入 `src/jmtorch/` 的接口。不要跳过迁入：草稿可以很乱，库路径要稳定。

1. **张量**（`practices/01_tensor/` → `src/jmtorch/tensor/`）  
   存储、形状、切片、广播、基础运算。先能表示数据，再谈求导。
2. **自动求导**（`practices/02_autograd/` → `src/jmtorch/autograd/`）  
   计算图、`backward`、梯度累积。张量运算要能留下可反传的痕迹。
3. **神经网络**（`practices/03_nn/` → `src/jmtorch/nn/`）  
   `Module`、线性层、激活、损失，接到 autograd。第一层就应该能反传。
4. **优化器**（`practices/04_optim/` → `src/jmtorch/optim/`）  
   `step` / `zero_grad`，至少实现 SGD。
5. **数据**（`practices/05_data/` → `src/jmtorch/data/`）  
   `Dataset` / `DataLoader`。玩具数据即可，重点是按 batch 取出。
6. **训练循环**（`practices/06_training/` → `src/jmtorch/training/`）  
   取 batch → 前向 → 损失 → 反传 → 更新。损失应能下降。入口占位：`scripts/run_training.py`。
7. **导出**（`practices/07_export/` → `src/jmtorch/export/`）  
   权重保存与加载；固定对外导入路径。入口占位：`scripts/export_checkpoint.py`。

把激活、层、损失放在自动求导之后：**先求导再接线层**，便于第一层就能反传。

本骨架没有卷积、注意力、量化等后续课。需要时再加 `practices/08_*`，不要塞进现有阶段把接口搅乱。

### 完成一阶段的标志

- 草稿里的行为已经收敛
- 稳定接口已迁入 `src/jmtorch/<子包>/`
- 对应 `tests/test_<阶段>.py` 有真实断言
- 下一阶段只 `import jmtorch...`，不再依赖 `practices/` 里的临时名字

现在打开 `practices/01_tensor/README.md` 和 `practice.py`，开始第一阶段。

## 4. 日常怎么测、怎么跑脚本

各阶段测试文件（`tests/test_tensor.py` 等）是占位，没有断言，pytest 不会当失败。实现某阶段后，把断言写进对应文件，再单独跑：

```bash
pytest tests/test_tensor.py
pytest tests/test_autograd.py
```

阶段名与文件对应：`tensor`、`autograd`、`nn`、`optim`、`data`、`training`、`export`。

### 脚本

| 脚本 | 将来做什么 | 现在 |
| --- | --- | --- |
| `scripts/run_training.py` | 调用训练循环 | 只有说明，没有训练 |
| `scripts/export_checkpoint.py` | 写出或读入权重 | 只有说明，没有写文件 |

实现第 6、7 阶段后再把这两个入口接上。在此之前运行它们应直接退出或打印「尚未实现」，不要假装训练成功。

## 5. 卡住了怎么查

按阶段缩小范围，不要一上来就整仓单步。实现某阶段后：

```bash
pytest tests/test_<阶段>.py
```

失败时：

```bash
pytest tests/test_<阶段>.py --pdb
```

或在可疑处写 `breakpoint()`。先看形状与 `.grad`，再查是否忘了 `zero_grad`。

### 常见排查顺序

1. **形状**：输入、权重、输出是否按你假设的维度对齐；广播是否悄悄改了语义。
2. **梯度**：`backward` 之后叶子张量有没有 `.grad`；多次反传是累积还是被覆盖。
3. **清梯度**：`step` 之前 / 之后有没有 `zero_grad`。忘了清，下一次更新会把旧梯度加进去。
4. **计算图**：有没有在不该断的地方用了纯 Python 数字，导致图断掉。
5. **数据**：`DataLoader` 取出的 batch 形状是否与层匹配。

调试时写一个只有几行的脚本或 pytest 用例：构造最小张量 → 前向 → 反传 → 打印 `shape` 与 `grad`。能在最小例子上说清楚，再回到完整阶段。

### 不要做的事

- 不要复制真实 PyTorch 的 C++ / Python 源码来「对照实现」。
- 不要把未迁入的 `practices/` 草稿当成稳定 API 去调试后续阶段。
- 不要在没有断言的占位测试上自我安慰：占位通过不代表功能对。

## 6. 给别人用、导出权重

这个包给其他项目用时，只安装仓库本身，不要拷贝 `practices/` 或测试进去。

在对方虚拟环境里：

```bash
pip install -e /path/to/jmtorch
```

然后只 `import jmtorch` 及其子包。不要 `sys.path.append` 到本仓库的 `practices/`。

版本写在两处，必须一致：

- `pyproject.toml` 的 `version`
- `src/jmtorch/__init__.py` 的 `__version__`

当前都是 `0.1.0`。改版本时两处一起改。

### 建议的公开表面（实现之后）

| 能力 | 建议导入 |
| --- | --- |
| 张量 | `jmtorch.Tensor` 或 `jmtorch.tensor.Tensor` |
| 反传 | `backward` |
| 模块 / 线性层 / 损失 | `jmtorch.nn.Module`、`Linear`、损失类 |
| 优化器 | `jmtorch.optim.SGD` |
| 数据 | `jmtorch.data.Dataset`、`DataLoader` |
| 训练 | `jmtorch.training.fit` |
| 权重 | `jmtorch.export.save`、`jmtorch.export.load` |

这些名字现在还不存在。实现第 7 阶段时再冻结它们。一旦其他项目开始 `import`，就不要随意改路径。

### 导出检查点

`src/jmtorch/export/` 负责保存与加载权重。`scripts/export_checkpoint.py` 是命令行入口占位，实现后应调用 `export.save` / `export.load`，而不是自己另写一套格式。

建议：

- 保存的是层权重，不是整个 Python 进程
- 加载后能继续 `forward`（训练循环接上后，损失曲线应能接着走）
- 文件格式由你定，但导入路径保持 `jmtorch.export`

### 不要导出的东西

- `practices/` 草稿
- 测试夹具
- `.venv`
- PyTorch 的任何源码
